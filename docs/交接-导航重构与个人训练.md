# 交接说明：教练端导航重构 + 个人训练板块

> 这份文档是设计讨论的结论汇总，用于在新对话里接着开发。
> 讨论日期：2026-10-03

---

## 一、要解决的问题

教练端导航分组标准不统一：「教学」按服务对象分，「内容」按东西类型分，两把尺子混用，
所以后加的功能（计时器、消息、统计、邀请码）全往「内容」里塞，越来越乱。

更根本的是：**教练自己的训练在产品上不存在**。
- 生理周期塞在「我的主页」里，跟语言设置并排
- 自我练习记录代码里写死 `userRole === 'CLIENT'`，教练账号练完不留记录
- 身体测试点进去是学员列表，没有"我自己"
- 计时器放在「内容」组，但它是个练的工具

---

## 二、硬约束

**只改教练端，学员端一个像素都不变。**

| 位置 | 教练分支 | 学员分支 |
|---|---|---|
| `app/dashboard/layout.tsx` | `trainerNav` / `trainerTabs` 改 | `clientNav` / `clientTabs` **不动** |
| `app/dashboard/page.tsx` | `featureEntries` 教练分支 改 | 学员分支 **不动** |

新增的「我的训练」页面要加角色限制，学员进不去。

⚠️ **最容易误伤的点**：生理周期现在在「我的主页」(`app/dashboard/profile/page.tsx`)，
而那个页面教练和学员**共用**。不能"挪"，只能在教练端**新增**入口，
我的主页保持原样，否则学员那边会丢功能。

计时器、课后作业等共享页面同理：只改「从哪里进去」，不改页面本身。

---

## 三、已定方案

### 3.1 底栏（教练端）4 个

```
首页     学员     我的训练     我的
```

依据：用户自报最常点的是 首页 / 学员 / 我的，加上新的我的训练。
原来的「课程」「计划」不是日常高频入口，收进首页宫格。

### 3.2 首页

```
10月3日 周六                        🔔  ← 消息改成右上角铃铛带红点
你好，jessicayang

 一   二   三   四   五   六   日     [月历 ›]
 29  30   1    2   (3)   4    5       ← 周视图横条，有课的日子标点
  ·   ··        ·    ●                  默认选中今天
─────────────────────────────────
⚠ 37 节课待复盘                    ›   ← 有积压才出现，清完消失
─────────────────────────────────
今天的课                      + 新建
  09:00  廖一 · 私教课
─────────────────────────────────
全部功能
  教学    约课 / 可约时段 / 课程训练 / 课后作业 / 身体测试
  内容    动作库 / 教案模板 / 训练方案
  经营    统计 / 邀请码
```

决策要点：
- **日历用周视图不用月视图**：手机上月历格子占大半屏。想看整月点 `[月历 ›]`
- **独立的「课程日历」入口取消**，并进首页周条（现有月视图页面保留，只改入口）
- **三个数字卡片（本月课程 / 学员数 / 待复盘）全部去掉**。月初「本月课程」几乎总是 0，
  「学员数」几个月不变；只有「待复盘」有信息量，改成可点的提醒横条
- **身体测试在「教学」组里保留入口**：有时候做体测本身就是一节课的内容。
  同一功能多入口是有意的（学员详情页里也能进）

### 3.3 我的训练（新板块）

```
我的训练
  [ ▶ 开始练 ]                      → 计时器
  本周 2 次 · 力量1 普拉提1          → 频次统计
  训练记录  ›
  身体数据  ›   → /dashboard/assessments/{自己的user.id}
  生理周期  ›   → 教练端新增入口（我的主页那份保留不动）
```

- **身体数据**：体测数据本来就按 user_id 存，几乎不用动后端。
  ⚠️ 需实测：`/dashboard/assessments/[clientId]` 原本假设看的是别人，
  以教练身份看自己能否正常跑要验证
- **计时器**：需要把记录功能对教练账号开放（现在 `app/dashboard/timer/page.tsx`
  里 `const isClient = userRole === 'CLIENT'` 卡住了）

### 3.4 训练记录（这次的主体）

定位：**手动补记为主**，计时器只是其中一种录入方式。
用户原话："平常的力量训练、普拉提训练都要记录进去"。

记录细度（用户明确要求细）：

```
一条训练记录
  日期 / 标题 / 类型（力量·普拉提·其他）/ 总时长 / 备注
  └ 动作明细
      动作名 · 组数 × 次数 · 重量 · 备注
```

- 动作**优先从动作库选**，库里没有的复用已有的「就地新建动作」
  （实现在 `app/dashboard/classes/[id]/page.tsx` 的 `handleQuickCreateExercise`）
- ⚠️ 即便第一版不画趋势图，录入时也要尽量关联 `exercise_id`。
  数据只能当下记、补不回来；现在随手打字，以后想看趋势那段历史就废了

## 四、数据结构

**用户明确要求：教练自己的训练跟学员数据分开存。**

新建两张表，与 class 系统平行但独立：

```sql
personal_workout
  id, user_id, date, title,
  type            -- 'strength' | 'pilates' | 'other'
  duration_min, notes,
  source          -- 'manual' | 'timer'
  created_at, updated_at

personal_workout_exercise
  id, workout_id,
  exercise_id     -- 可空，关联动作库；为空表示自由填写
  name            -- 冗余存一份名字，动作库删了也不丢记录
  sets, reps, weight, weight_unit,
  duration_sec, rest_sec, notes, order_num
```

**学员的自我练习维持现状**，继续存在 `class` 表（`class_type='self_practice'`），
不迁移、不改动。理由：学员的训练记录就该是"上了什么课 + 自己练了什么"的完整时间线，
混在一起加筛选是合理的，而且已经在用。问题只出在教练这一侧——
教练的个人训练不是"一节课"，没有学员、没有收入、不需要复盘。

代价（已知并接受）：同一个"练完记录"按钮，教练点和学员点产生不同对象，
`/api/self-practice` 需要按角色分叉，要在代码里写清楚。

## 五、工作顺序

```
A  个人训练记录     新表 + 录入表单 + 列表          ← 最大的一块，先做
   导航重构         底栏4个 + 首页 + 宫格分组       ← 独立，可穿插
C  频次统计         本周/本月练了几次，按类型分
B  趋势图           推迟
```

**趋势推迟的原因**（用户决定）：第一版只做频次，因为它不依赖动作库质量，现在就能准。
单个动作进步曲线、总训练量（组×次×重量）等动作库完善、实际用起来之后再做。

趋势真要做的时候：
- 学员那边**不用新建数据**，组次重量一直存在 `class_exercise_instance`，
  还有每组明细 `exercise_instance_set`
- 图表组件做一个，教练自己和学员两边共用

## 六、这个项目已经踩过的坑（新对话务必知道）

1. **`onAuthStateChange` 回调里绝对不能调用任何 supabase 方法** —— 会跟认证锁死锁，
   表现为登录转圈到超时。详见 `context/AuthContext.tsx` 顶部注释
2. **`class.class_type` 有 CHECK 约束**，加新值要先改约束
3. **自我练习必须排除在 `/api/stats`、`/api/dashboard`、`/api/classes` 之外**，
   否则虚增课时。新增 class 查询时要记得
4. **数字输入框不要用 `type="number"`** —— 受控组件下浏览器会吞掉输入，
   表现为"这个 1 删不掉"。用 `type="text"` + `inputMode="numeric"` + 正则过滤
5. **动态创建的组件要定义在页面组件外面**，否则每次 render 重建，输入框焦点每敲一个字就丢
6. **站内消息按角色强制隔离**，见 `lib/notifications.ts` 的 `NOTICE_TYPES` 登记表
