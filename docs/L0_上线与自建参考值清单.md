## 一、L0 现在就能上线，没有前置条件

```bash
cd ~/my-fitness-pro
npm run dev
```

打开 `http://localhost:3000/dashboard/assessments` → 点任一学员。

数据库改动已经推到线上的 Supabase 项目（`my-pilates-pro`），不需要另跑 migration。

**先做这两步才看得到东西**（L0 表现在是空的）：

1. 进「档案与禁忌」页 → 填性别、出生日期 → 保存档案。
   不填这两项，年龄、HRmax、SMI 的参考值都出不来。
2. 回「基础 / 体成分」页 → 照着一张 BIA 报告录一遍 → 创建测量记录。
   派生值（BMI / 脂肪量 / 去脂体重 / SMI / FFMI / BMR / 腰臀比 / 腰高比）保存后自动出现。
   录第二次测量后，「与上一次测量比较」区才会显示 MDC 判定。

确认后：

```bash
npm run build     # 沙箱跑不了（SWC 是 macOS 版），需你本地确认
git add -A && git commit -m "L0 基础数据层" && git push
```

### 已用弱化措辞处理，不需要样本

| 字段 | 原来源 | 处理方式 |
|---|---|---|
| B06 体脂率 | ACSM / ACE | 只说落在第几档，不用评价词，附 BIA ±3% 误差提醒 |

| B12 内脏脂肪 | 设备厂商分级 | 强调跨设备不可比，与同一台机器的历史对照 |
| B13 细胞外水比 | 设备厂商区间 | 提示受当日水分与训练状态影响，宜连续观察 |

### 无关版权

派生公式（BMI、脂肪量、去脂体重、FFMI、Katch-McArdle、Tanaka）是数学公式，不受版权保护。

## 三、还值得做的一件事：冻结测试协议

**这件事跟法律无关，是数据质量问题。**

MDC 判定的前提是前后测法一致。同一个「俯卧撑」，标准版和跪姿版的数字差两倍；
换一台握力计，读数整体偏移。协议一变，会员就没法跟自己上个月比 —— 这是 L0/L1 都要的基础，
跟建不建常模没有关系。

需要你逐项写死并从此不改：

| 项目 | 必须定死的细节 |
|---|---|
| BIA 体成分 | 设备型号；测量条件（建议：课前、当日未训练、已排空 —— 一致性比理想条件重要） |
| 围度 | 软尺；腰围量髂嵴上缘还是脐水平（系统已有 `waist_landmark` 字段，选定后统一） |
| 握力 | 器材型号；哪只手；测几次；取最大值还是均值 |
| 俯卧撑 | 标准版 or 跪姿（选一个；两者都用就必须分成两个独立指标） |
| 30 秒坐站 | 椅子高度；是否可扶；手臂位置 |
| 闭眼单腿站立 | 哪条腿；是否穿鞋；手臂位置；终止条件 |
| 坐位体前屈 | 器材型号（不同箱子零点不同）；屈膝与否 |

**交付物**：你口述或写个草稿，我整理成协议文档，并把关键约束写进录入页的提示文案。

设备型号系统里有 `device_model` 字段，每条记录都存，换设备时能查到断点在哪。

样本量看板视图 `l0_norm_readiness` 已建好，将来要用时随时能查每个格子攒了多少人
